## 修复“搜索后显示空白”bug（升至 v1.3.2）

根因：克隆京东原生卡片时仅清除了 `hideNativeProducts()` 写入的**内联** `display:none`，但京东页面 CSS 通过**类名**（lazy/hidden 等变体）隐藏卡片，`card.style.display=''` 还原为 class 级 `display:none` → 结果面板空白。

修复（`src/ui/products.js`）：先把 `grid` 挂载到面板，再逐卡片用 `getComputedStyle` 检测 `card`/`img`/`img.parentElement` 实际 `display==='none'` 时强制 `'block'` 兜底。`src/ui/results.js` 为空状态浮层 `.jds-empty-overlay` 补显式背景/边框/圆角/阴影（Light DOM 不继承 Shadow 组件样式）。

版本号统一升至 1.3.2（23 个 JS 文件头 + manifest/package/metadata + prototype 徽标 + README 打包名）；CHANGELOG 与 openspec/tasks 补 v1.3.2 条目。验证：`search_bug_test.js` 真实 DOM 模拟 9 项断言全过（面板创建、可见、2 卡片、名称/链接填充、无匹配空状态）。临时测试文件已删除。

## 继续修复“搜索结果不显示”bug（升至 v1.3.3）

v1.3.2 的 `getComputedStyle` 兜底仍不足以覆盖真实页面：**京东虚拟列表/懒加载会把克隆卡片的内容高度压为 0（display 非 none）**，导致结果面板整片空白但 `display` 正常。原克隆方案还继承京东列表容器的 flex/`!important` 布局，脆弱且依赖京东真实 DOM。

修复（`src/ui/products.js`）：
- `renderProducts` 改为**统一使用扩展自带网格容器**（内联 `display:grid` 等，避免继承京东列表布局干扰）。
- 对每张克隆京东原生卡片做**实测可见性校验**：挂载后若 `getComputedStyle(card).display==='none'` 或 `getBoundingClientRect().height===0`（零高度/虚拟列表），自动 `replaceChild` 为扩展自带内联样式卡片（`_buildOwnCard`：a 标签卡片，图片+标题+价格，京东红主色，主图失败回退 📦，新窗口打开，悬停阴影）。
- 无原生模板时也走 `_buildOwnCard`。
- 删除原 `_renderFallbackCards`，由 `_buildOwnCard` 承担兜底；`_fillNativeCard` 保留用于克隆卡片填充。

验证：临时 `verify_render.js`（最小 DOM 桩 + results.js）四路径全过——无模板→2 张自带卡片、有模板可见→2 张克隆卡片、有模板零高度→回退自带卡片(a)、空商品→空状态。临时脚本已删除。
版本统一升至 1.3.3（26 个 JS/JSON + prototype 双徽标 + README/README_EN 打包名）；CHANGELOG/openspec/tasks/spec 同步。

## 搜索结果仍不显示 → 彻底弃用克隆原生卡片（升至 v1.3.4）

v1.3.3 仍失败。用 **jsdom 全链路集成测试**（临时 `itest.js`：加载全部 22 个 src 脚本 + content.js，模拟京东拍卖页 `div.auction_head`+`div.gl-warp>div.gl-item`，触发搜索输入）复现：jsdom 下 `getBoundingClientRect().height` 恒为 0 → 兜底总是触发 → 渲染出 2 张自带卡片、面板 `is-visible`、过滤正确（"手机"命中 2 条、无匹配显示空状态），**无运行时异常**。

关键结论：jsdom 因 height=0 走了兜底才“正常”；真实浏览器中克隆京东原生卡片测量为 `display:block` 且 `height>0`（被判“可见”）却被京东 class 级 CSS 渲染成**整片空白**（尺寸正常却不可见）——原 `getComputedStyle`/`getBoundingClientRect` 兜底对这种状态完全失效，且无法可靠判定“空白但尺寸正常”。

最终方案（`src/ui/products.js`）：**彻底删除克隆京东原生卡片路径**，`renderProducts` 一律调用 `_buildOwnCard` 渲染扩展自带内联样式卡片（a 标签、图片+标题+价格、京东红 `#e1251b`、主图失败回退 📦、新窗口打开、悬停阴影），完全脱离京东 DOM/CSS 依赖，任意京东页面都稳定可见。删除 `_fillNativeCard`（不再使用）。

验证：jsdom 集成测试确认搜索"手机"渲染 2 张 `a.jds-result-card`（"苹果手机 Pro¥1,999"、"小米手机 青春版¥799"），无匹配显示空状态，无异常。临时 `itest.js`/`verify_render.js`/`bump_version.js` 及输出已删除；jsdom 经 `npm i --no-save` 安装（未写入 package.json，node_modules 已被 .gitignore 忽略）。
版本统一升至 1.3.4（26 个 JS/JSON + prototype 双徽标 + README/README_EN 打包名）；CHANGELOG/openspec/tasks/spec 同步。

## 修复“清空搜索按钮失效”bug（升至 v1.3.5）

根因不在按钮逻辑（clear 处理器正确置空 keyword 并调用 onClear→_applyFilterAndUpdate 恢复原生列表），而在**结果面板宿主 `#jds-results-host`**：它是 `position:fixed; inset:0; z-index:999990` 的全屏透明覆盖层，却**未设 `pointer-events`**。搜索激活时该覆盖层盖住整个视口，把嵌入在 `auction_head` 里的工具栏（页面级 z-index 低于 999990）挡在下面并拦截点击 → 清空/搜索按钮点不到（"失效"）；清空后宿主仍在 DOM 中，继续拦截整页点击。

修复（`src/ui/results.js` `RESULTS_HOST_CSS`）：宿主加 `pointer-events:none`，结果面板 `.jds-results-panel` 与空状态 `.jds-empty-overlay` 加 `pointer-events:auto`。这样透明覆盖层不拦截点击（工具栏/页面可交互），结果面板自身仍可交互（卡片点击）。

验证：jsdom 清空按钮测试 10 项断言全过——搜索后面板 is-visible/原生隐藏/清空按钮可见、宿主样式含 pointer-events:none、面板含 pointer-events:auto、点击清空后面板隐藏/输入框空/关键词空/原生恢复/清空按钮隐藏。临时 `clear_test.js`/`clear_out.txt`/`bump_version.js` 已删除。

**经验**：全屏 fixed 覆盖层必须显式设 `pointer-events:none`（交互区再设 auto），否则会拦截其下方/嵌入元素的点击，是扩展常见隐性 bug。

**经验**：依赖目标页面 DOM/CSS 的克隆渲染在扩展中极脆弱，应优先用自带内联样式卡片保证可见性。
